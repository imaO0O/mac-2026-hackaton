# План работы: 3 участника, у каждого GPU

Таймлайн рассчитан на **48 часов**. Если у вас 24 или 72 — сжимайте/растягивайте
фазы пропорционально, но контрольные точки и порядок не меняйте: смысл в том, что
сквозной цикл работает с первых часов, а дальше каждый улучшает свою часть.

## Принцип разделения

Делимся **по агентам**, а не по этапам обработки. Стык один — `src/nefte/agents/schemas.py`.
Пока контракт стабилен, любой агент можно заменить заглушкой, и демо всё равно
соберётся. Это же и защита от главного риска хакатона: «у всех всё почти готово,
но вместе не собирается».

Скелет уже работает: `python scripts/run_cycle.py --window bad_data_frozen_pak`
проходит полный путь данные → 4 агента → рекомендация оператору и логирует прогон
в `reports/runs/`. Ваша задача — заменить базовые реализации на настоящие, не
трогая контракт.

## Роли

| | Участник 1 — «Качество» | Участник 2 — «Надёжность и данные» | Участник 3 — «Оптимизация и демо» |
|---|---|---|---|
| **Агент** | Агент качества | Агент надёжности + контроль достоверности | Агент оптимизации + оркестратор |
| **Файлы** | `agents/quality.py`, `models/`, `data/features.py` | `agents/reliability.py`, `data/cleaning.py`, `models/anomaly.py` | `agents/optimizer.py`, `agents/orchestrator.py`, `app/` |
| **Ключевой результат** | прогноз серы с интервалом + суррогат «режим → качество» | severity-индекс, ограничения, детектор недостоверных данных | допустимые сценарии, выбор, объяснение, дашборд |
| **GPU-нагрузка** | обучение моделей: CatBoost `task_type=GPU` + PyTorch TCN/GRU с квантильной потерей | LSTM-автоэнкодер для аномалий, свипы гиперпараметров | локальная LLM для объяснений (Ollama/vLLM) + батч-инференс суррогата на сетке сценариев |
| **Критерии ТЗ** | «Качество прогноза», «Работа с данными» | «Надёжность», «Работа с данными» | «Оптимизация и безопасность», «Объяснимость», «Демонстрация», «Воспроизводимость» |

Мультиагентность в ТЗ оценивается отдельно — три автора, три агента, обмен через
типизированные структуры, это видно и в коде, и на демо.

## Таймлайн

### T+0 … T+3 — общий старт (все вместе, за одним столом)
* каждый: `pip install -r requirements.txt`, `python scripts/prepare_data.py`,
  `pytest -q` (12 тестов должны пройти), `python scripts/run_cycle.py --ts "2026-04-20 12:00"`;
* прочитать `docs/DATA_NOTES.md` — все ловушки уже найдены, не тратьте на них время заново;
* договориться и **заморозить** `schemas.py`. Любое изменение контракта позже —
  только общим решением, отдельным коммитом, с уведомлением всех.

**Чекпоинт 1 (T+3):** у всех троих скелет запускается и тесты зелёные.

### T+3 … T+12 — параллельная работа, первая версия каждого агента

**У1.** Датасет: телеметрия (очищенная) + as-of признаки ЛИМС/ПАК с возрастом +
лаги 1/2/6/12 ч и скользящие средние. Обучить CatBoost (GPU) на серу с горизонтом
2 ч, замерить MAE/RMSE на val. Квантильные модели (q05/q50/q95) — интервал берём
из них, а не из фиксированной σ. Отдать `QualityAgent.predict` и суррогат.

**У2.** Перевести находки из `DATA_NOTES` в код-детекторы: заглушки 307/313,
полки, отрицательные расходы, обрыв ПАК, устаревание ЛИМС. Отдать
`data_quality_flags`, которым верит оркестратор. Собрать severity: WABT, ΔP Р-202,
`T55`, скорость изменения; нормировка — **по train-периоду** (сейчас в baseline
берётся вся история, это надо исправить).

**У3.** Оптимизатор: сейчас случайное сэмплирование — заменить на сетку + локальный
поиск, добавить `throughput_fn` (отбор ДТ по `F17`/`F30`) и `energy_proxy`
(пар + топливо печей). Настроить Парето-фронт и вывод 3 альтернатив. Поднять
Streamlit-скелет: временная шкала, состояние, карточка рекомендации.

**Чекпоинт 2 (T+12):** каждый агент отдаёт свою структуру на реальных данных;
`run_cycle.py` проходит по всем четырём демо-окнам без исключений.

### T+12 … T+24 — качество моделей

**У1.** PyTorch-модель последовательностей (TCN или GRU) на GPU, вход — окно
6–24 ч телеметрии + возраст анализов. Сравнить с CatBoost честно на val, выбрать
победителя, зафиксировать сид. Калибровка вероятности нарушения (reliability
diagram) — оркестратор принимает решения именно по ней. SHAP для `drivers`.

**У2.** LSTM-автоэнкодер на GPU для аномалий режима, порог по train-квантили.
Бэктест severity: показать, что индекс растёт перед известными эпизодами
(рост серы, зависания ПАК). Написать тест «нет утечки»: любые признаки в момент t
не используют данные позже t.

**У3.** Оркестратор: правила разрешения конфликта целей, пороги отказа, лимит
частоты воздействий (не чаще чем раз в N часов). Объяснения через локальную LLM:
на вход — структуры агентов, на выход — текст для оператора; **числа берутся из
структур, LLM только формулирует** (галлюцинации в рекомендации недопустимы).

**Чекпоинт 3 (T+24):** метрики прогноза на val зафиксированы в `reports/`,
дашборд показывает полный цикл, объяснения генерируются.

### T+24 … T+36 — сборка и жёсткая проверка
* прогон на **test** (2026) — впервые, без подгонки;
* сценарий блендинга: модельный блок смешения с проверкой суммы долей = 100 %
  и пересчётом серы по смеси (У3 + У1), допущения — в `DATA_NOTES`;
* У2 гоняет «злые» кейсы: обрыв ПАК, устаревший ЛИМС, заглушки 307 в ключевых
  тегах, скачок сырья. Система обязана отказываться, а не фантазировать;
* фиксация `requirements.txt`, проверка «с нуля на чужой машине» (У3).

**Чекпоинт 4 (T+36):** заморозка кода моделей. Дальше — только демо, тексты и
исправление падений.

### T+36 … T+44 — демонстрация
* У3 собирает сценарий показа: 4 окна из `demo_windows`, в каждом видно, как
  агенты обмениваются оценками и как рождается решение;
* У1 готовит слайд «качество прогноза»: метрики, интервалы, что модель видит;
* У2 — слайд «надёжность и достоверность»: что забраковано и почему, severity;
* репетиция целиком, дважды. Ноутбук с GPU для демо — один, заранее выбранный.

### T+44 … T+48 — резерв
Резерв не «на всякий случай», а запланированный: в него всегда что-то падает.

## Правила совместной работы

* ветки `feat/quality`, `feat/reliability`, `feat/optimizer`, PR в `main`;
* `main` всегда зелёный: `pytest -q` перед каждым PR;
* контракт `schemas.py` меняем только все вместе;
* сиды фиксированы (`configs/config.yaml → random_seed`), любой результат
  воспроизводится командой из README;
* каждое допущение — строкой в `docs/DATA_NOTES.md` с пометкой «допущение»;
* тяжёлые артефакты (модели, кэш, csv) в git не кладём — `.gitignore` уже настроен.

## Риски и план Б

| Риск | Признак | План Б |
|---|---|---|
| Модель серы не лучше персистенции | MAE на val ≥ базовой 1.7 | оставить персистенцию + честный интервал; выигрывать объяснимостью и безопасностью, а не R² |
| Слабые связи «режим → качество» | суррогат почти не меняет прогноз | перейти на ранжирование сценариев по риску и severity, а не на точечную оптимизацию |
| LLM тормозит или врёт | демо буксует | шаблонные объяснения из структур (в скелете уже есть), LLM — опция |
| Не собирается вместе | несовпадающие поля | контракт заморожен на T+3, любые правки — общим коммитом |
| Данные не влезают в память | OOM на 247 МБ csv | parquet-кэш + чтение только нужных тегов (`load_telemetry(columns=…)`) |
