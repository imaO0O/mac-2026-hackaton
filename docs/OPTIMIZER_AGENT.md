# Агент оптимизации, оркестратор и дашборд

Участник 3. Всё на CPU: один цикл принятия решения считается за доли секунды,
дашборд поднимается локально без интернета.

```bash
streamlit run app/dashboard.py
python scripts/run_cycle.py --window quality_risk --every 10D
```

## Как ищутся варианты

Случайное сэмплирование заменено на три слоя, все дешёвые по вычислениям:

1. **«Ничего не делать»** — обязательный кандидат. Без него система вынуждена
   что-то менять каждый цикл, а ТЗ прямо требует не создавать лишних воздействий
   в устойчивом режиме.
2. **Покоординатная сетка** — по одному изменению за раз, 5 уровней на каждую
   уставку. Оператору такая рекомендация понятнее всего: «подними температуру
   на градус», а не «поменяй одновременно четыре параметра».
3. **Комбинации + локальное уточнение** вокруг лучшего найденного варианта.

Область поиска — пересечение трёх ограничений: модельный диапазон (квантили
обучающего периода, допущение), сужение от агента надёжности и максимальный шаг
за цикл. Если текущее значение тега уже вне разрешённого диапазона, вариант не
оставляет его как есть, а возвращает к ближайшей границе — и показывает это
оператору отдельным изменением.

## Два уровня допустимости

Первая версия проверяла жёстко: прогноз плюс запас в 1σ должен укладываться в
10 мг/кг. При σ ≈ 1.4 и типичном уровне серы 8.4 это отсекало почти всё, и
система отказывалась даже там, где могла помочь. Теперь допустимы два случая:

| Уровень | Условие | Как показывается |
|---|---|---|
| **С гарантией** | прогноз + запас ≤ предела | обычная рекомендация |
| **Без гарантии** | прогноз ниже, чем при бездействии | предупреждение + уверенность × 0.6 |

Варианты с гарантией всегда стоят в ранжировании выше — гарантия важнее свёртки
критериев. Если не проходит ни один, система отказывается и называет причину:
качество, модельный диапазон или запрет агента надёжности.

## Критерии

Ранжируются **только допустимые** варианты — экономика не может перевесить
нарушение спецификации. Свёртка: запас по качеству 0.45, выпуск 0.25, энергия
0.15, тяжесть режима 0.15. Параллельно считается ранг Парето по четырём
критериям, оператору показываются три **различающиеся** альтернативы (три почти
одинаковых варианта бесполезны).

Прокси, оба с явными допущениями:

* **выпуск** — гидроочищенное ДТ (`F17`), меняется пропорционально расходу сырья;
* **энергозатраты** — топливо печи П-3 сверх 370 °C, нагрев ГСС сверх 350 °C,
  прокачка сырья и пар в колонны АВТ, с фиксированными весами.

Абсолютные значения прокси смысла не имеют, важно, что сравнение вариантов между
собой воспроизводимо.

## Правила оркестратора

* **Отказ при недостоверных данных** — раньше проверки допустимости.
* **Отказ, если допустимых вариантов нет**, с расшифровкой причины отсева.
* **Лимит частоты воздействий:** не чаще раза в 4 часа. Качество реагирует с
  запаздыванием, дёргать уставки каждый цикл — вредно. Лимит переступается
  только если продукт **уже** вне спецификации: просто высокий риск ожидания
  не отменяет.
* **Эффект показывается относительно бездействия**, а не в абсолюте: «сера
  −0.03 мг/кг, выпуск +2.06 %, энергия −1.84 %» говорит оператору больше, чем
  голое «8.76 мг/кг». Точка отсчёта считается всегда, даже когда само бездействие
  недопустимо.
* **Конфликт целей называется вслух:** если агент надёжности сузил диапазон,
  объяснение прямо говорит, что вариант выбран внутри ограничения, а не по
  максимуму качества.

## Дашборд

`app/dashboard.py` — Streamlit, четыре демо-сценария из `configs/config.yaml`,
ползунок времени с шагом 6 часов. Показывает: строку состояния (ПАК, ЛИМС с
возрастом, прогноз с риском, тяжесть режима), карточку рекомендации с таблицей
изменений и проверенными ограничениями, график серы с лабораторными точками и
подсвеченными зависаниями анализатора, факторы тяжести режима, таблицу
альтернатив, фронт Парето и полный JSON ответов агентов.

Данные и модель кэшируются (`st.cache_resource`), поэтому смена момента времени
пересчитывается мгновенно. Первая загрузка — около полуминуты.

## Что осталось сделать

1. **Блендинг.** В пакете нет ни компонентов, ни присадок, ни резервуаров,
   поэтому блока смешения нет вовсе. Его придётся строить как модель на явных
   допущениях: доли компонентов, правило смешения по сере и плотности, проверка
   суммы долей = 100 %. Это единственное требование ТЗ, не закрытое кодом.
2. **Веса свёртки** (0.45 / 0.25 / 0.15 / 0.15) выбраны разумно, но не
   обоснованы данными — под защиту стоит показать чувствительность решения к ним.
3. **Слабая чувствительность прогноза к уставкам** (ограничение агента качества)
   делает фронт Парето узким: варианты различаются сотыми долями мг/кг. Пока это
   главный ограничитель полезности оптимизатора.
