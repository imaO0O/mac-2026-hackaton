# Что нужно, чтобы поставить это на установку

Эксперты назвали развёртывание критерием оценки дважды. 11.09, 03:57: «мы
рассматриваем ваши решения прототипа с точки зрения возможности развертывания их на
производстве… на производстве работает технологическая сеть передачи данных, и она
никак не связана с внешним интернетом». И 12:50, про критерии: «архитектурная
грамотность системы и возможность, как вы говорили, запуска её в закрытой среде
будет важна».

Документ отвечает на один вопрос: **что должен сделать интегратор, чтобы это
заработало в цехе**, и где проходят границы того, что сделано.

## 1. Точка стыковки — одна

Вся система принимает ровно один объект — срез состояния `ProcessState`
(`src/nefte/agents/schemas.py`): телеметрия АВТ и 24-2000, лабораторные значения с
их возрастом, показания поточных анализаторов и оценка пригодности данных. Адаптер
к системе сбора (историческая база, OPC UA, шина) обязан собрать такой срез — и
больше ничего.

Обратно приходит `Recommendation`: проблема, действие по тегам, ожидаемый эффект,
проверенные ограничения, уверенность, объяснение, рецептура смешения и трасса
решения по агентам. Карточка оператора — это её текстовый вид
(`Recommendation.to_operator_text`, разбор по строкам — `docs/CARD.md`).

Служба поднимается одной командой и работает на стандартной библиотеке Python —
доустанавливать в закрытом контуре нечего:

```bash
python -m nefte.service            # http://127.0.0.1:8080
```

| Метод | Что делает |
|---|---|
| `GET /health` | жив ли сервис и какая модель качества подключена |
| `GET /decide?ts=…` | решение на момент истории (срез собирается из файлов, как в демо) |
| `POST /decide` | решение по присланному срезу `ProcessState` |
| `POST /ask` | вопрос оператора своими словами; работает только при включённом слое локальной LLM |

## 2. Что делать с интернетом: ничего

Система не ходит наружу. Это не обещание, а проверка: `scripts/check_offline.py`
собирает систему, считает несколько решений и импортирует библиотеки дашборда
внутри запрета сетевых обращений (`nefte.offline.forbid_network`) — любая попытка
разрешить внешнее имя или открыть соединение падает с именем адреса. То же на
синтетическом срезе — `tests/test_runs_offline.py`.

Единственное, что требует сети, — **установка зависимостей**. В закрытом контуре её
делают из заранее собранного каталога колёс:

```bash
pip download -r requirements.txt -d wheels     # на машине с интернетом
pip install --no-index --find-links wheels -r requirements.txt   # в контуре
```

Обучение и пересборка отчётов тоже идут локально: `bash scripts/reproduce_all.sh`.
Видеокарта нужна только нейросетевым вариантам моделей (`docs/GPU_SETUP.md`); всё
рабочее решение считается на процессоре.

## 3. Локальная LLM — необязательный слой

Организаторы сказали (11.09, 04:34 и 07:12), что внутри сети есть локальная LLM с
OpenAI-совместимым API и моделями примерно до 30 млрд параметров. Слой под это
написан и **выключен по умолчанию** (`llm.enabled: false`). Включается адресом
сервиса в конфиге:

```yaml
llm:
  enabled: true
  base_url: "http://<адрес-локальной-модели>/v1"
  model: "<имя модели>"
```

Правило, без которого слой был бы опасен: **модель не может принести ни одного
своего числа**. Ей передаётся структура решения, и каждое число ответа проверяется
на совпадение с ней; ответ с посторонним числом отклоняется, и оператор видит
шаблонное объяснение с пометкой, какое число не подтвердилось. Недоступность
сервиса — не сбой системы, а тот же возврат к шаблону.

## 4. Частота работы и обновление моделей

| Что | Как часто | Откуда взято |
|---|---|---|
| Расчёт решения | раз в час | организаторы назвали 15 минут — 1 час; признаки строятся на часовой сетке |
| Движение уставки | не чаще чем раз в 4 ч | постоянная времени канала серы 4.6 ч; 2 °C за 4 ч = 0.5 °C/ч |
| Возврат к базовому режиму | не раньше 14 ч после действия ради качества | 3τ ≈ 95 % отклика |
| Переобучение модели качества | при возрасте модели больше срока годности | срок выведен по деградации на валидации, `docs/QUALITY_AGENT.md` |

Возраст модели входит в уверенность: чем старше обучение относительно текущего
момента, тем ниже множитель. Это видно в карточке и на дашборде — отдельного
напоминания «пора переобучить» не нужно.

## 5. Что придётся доделать интегратору

Называем прямо, потому что на защите об этом спросят.

**Признаки считаются из файлов, а не из потока.** Обученная модель берёт строку
признаков из матрицы по метке времени среза. Для момента, которого нет в истории,
прогноза не будет, и агент качества перейдёт на персистенцию по измерениям среза.
Живой расчёт признаков по потоку — работа адаптера: те же окна (6, 36, 144 ч) на
скользящем буфере.

**Границы уставок — наши, а не паспортные.** Сейчас это квантили обучающего периода
(p05–p95). Эксперт 11.09 (25:56) сказал, что паспортных ограничений не будет: они
«очень-очень близко связаны с конфиденциальной информацией». При внедрении их
подставляют в `configs/config.yaml → limits`, и всё остальное работает как есть —
включая строку «Возврат в норму», которая считает шаги до диапазона.

**Состав товарного парка.** Смешение считает на допущениях: сера резервуара
7.5 мг/кг, доступность компонентов — по расходам из телеметрии. Реальные остатки и
качество по резервуарам приходят из системы товарного учёта, это ещё один адаптер.

**Роль системы — советчик.** Уставки система не пишет: она выдаёт карточку, а
решение остаётся за оператором и технологом. Замкнутый контур в проекте есть, но
только как имитация для проверки устойчивости (`scripts/run_simulation.py`), и это
намеренно: разрешать программе двигать режим без человека на установке с такой
ценой ошибки нельзя.
