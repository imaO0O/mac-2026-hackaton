# МАС «Нефтекод»: АВТ → гидроочистка → блендинг

Мультиагентная система, которая по состоянию процесса оценивает риск выхода за
спецификацию, сравнивает допустимые изменения режима и выдаёт оператору
объяснимую рекомендацию — либо мотивированно отказывается её давать.

Жёсткое правило системы: **качество и технологические ограничения выше экономики**.
Недопустимый режим нельзя компенсировать производительностью.

## Быстрый старт

```bash
git clone https://github.com/imaO0O/mac-2026-hackaton.git
cd mac-2026-hackaton
python -m venv .venv && .venv\Scripts\activate     # Windows
pip install -r requirements.txt
pip install -e .
```

Пути к данным — через переменные окружения (файлы в git не хранятся):

```bash
copy .env.example .env
set NEFTE_SOURCE_DIR=C:/путь/к/выдаче        # где лежат xlsx, pdf, data.rar
set NEFTE_DATA_DIR=C:/путь/к/локальным/данным # куда распаковать csv (НЕ в OneDrive)
```

Подготовка данных (распаковка архива + parquet-кэш, ~2 минуты, один раз):

```bash
python scripts/prepare_data.py
```

Проверка:

```bash
pytest -q
python scripts/run_cycle.py --ts "2026-04-20 12:00"
```

Ожидаемый вывод последней команды — отказ от рекомендации: в этот момент поточный
анализатор серы завис на 18.4 мг/кг, а лаборатория показывает норму. Умение
корректно отказаться — часть требований ТЗ.

Обучение агента качества (CPU, ~3 минуты) — без него система работает на
персистенции, с ним подключается виртуальный анализатор:

```bash
python scripts/train_quality.py --horizon 0    # виртуальный анализатор
python scripts/train_quality.py --horizon 2    # прогноз на 2 часа
```

Бэктест агента надёжности и отчёт по достоверности данных (CPU, ~1 минута):

```bash
python scripts/backtest_reliability.py
```

Дашборд оператора (локально, CPU, без интернета):

```bash
streamlit run app/dashboard.py
```

Рецептура смешения на заданный момент:

```bash
python scripts/run_blending.py --ts "2026-02-28 00:00" --additive 500
```

Демо-сценарии в консоли:

```bash
python scripts/run_cycle.py --window stable --every 20D                # устойчивый режим
python scripts/run_cycle.py --window quality_risk --every 10D          # риск по качеству
python scripts/run_cycle.py --window bad_data_frozen_pak --every 2D    # недостоверные данные
```

Каждый прогон пишется в `reports/runs/<timestamp>.json`: входной срез, ответы всех
агентов, итоговая рекомендация — чтобы логику решения можно было проверить.

## Как устроен один цикл

1. `StateBuilder.build(ts)` собирает срез: телеметрия обеих установок, последние
   ЛИМС и ПАК **вместе с возрастом**, флаги достоверности.
2. `QualityAgent` выбирает источник по приоритету ЛИМС → ПАК → ВАК, прогнозирует
   серу на горизонт и оценивает вероятность выхода за 10 мг/кг.
3. `ReliabilityAgent` считает тяжесть режима по прокси (WABT, ΔP Р-202, печь) и
   сужает диапазоны уставок.
4. `OptimizerAgent` генерирует варианты внутри модельных диапазонов, **отсекает
   недопустимые до ранжирования**, ранжирует свёрткой и по Парето.
5. `Orchestrator` выбирает итог: удержать режим, изменить уставки или отказаться —
   и объясняет решение.

## Текущее состояние

* **Агент качества — рабочий.** Виртуальный анализатор на CatBoost: MAE 1.26 мг/кг
  на тесте против 1.48 у поточного анализатора, ROC-AUC риска 0.82, покрытие
  интервала 0.86. Признаки режима реактора и монотонные ограничения по физике —
  `docs/REGIME_FEATURES.md`, метрики и ограничения — `docs/QUALITY_AGENT.md`.
* **Отклик на уставки даёт гибридный суррогат:** уровень серы берётся у модели,
  приращение считается по кинетике гидрообессеривания. Без него подъём температуры
  на 2 °C менял прогноз на 0.008 мг/кг, с ним — на 3.2, и оптимизатору стало из
  чего выбирать.
* **Агент надёжности — рабочий.** Детекторы достоверности переведены в код,
  severity нормируется строго по обучающему периоду, бэктест показал обратную
  связь тяжести режима с превышениями по сере (AUC 0.35 на тесте) — то есть
  конфликт целей подтверждён числом. Добавлены наработка катализатора, многомерный
  детектор аномалий и пороги risk_class из квантилей обучающего периода.
* **Останов установки распознаётся отдельно.** 20 эпизодов (3.9 % времени), где
  реактор холодный и сырья нет, раньше принимались за отказ датчиков — и система
  советовала остановленной установке поднять температуру. Этим же объясняются
  54 % «зависаний поточного анализатора»: через прибор ничего не идёт.
  Подробности — `docs/RELIABILITY_AGENT.md`.
* **Агент оптимизации и оркестратор — рабочие.** Поиск в три слоя (бездействие,
  покоординатная сетка, комбинации с локальным уточнением), прозрачные прокси
  выпуска и энергозатрат, фронт Парето, лимит частоты воздействий и два уровня
  допустимости: «с гарантированным запасом» и «улучшает, но без гарантии».
  Подробности — `docs/OPTIMIZER_AGENT.md`.
* **Блок смешения — рабочий.** Данных по компонентам в пакете не выдано, поэтому
  модель построена на явных допущениях. Главный вывод: прямогонную фракцию под
  Евро-5 подмешать нельзя (предельная доля 0.013 %), единственный рычаг по сере —
  глубина гидроочистки. Подробности — `docs/BLENDING.md`.
* Что делать дальше — `docs/PLAN.md`.

## Допущения

Все допущения собраны в `docs/DATA_NOTES.md` §5 и помечены в `configs/config.yaml`

а не выданные организаторами.
